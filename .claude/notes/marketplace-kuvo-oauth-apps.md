# Marketplace OAuth registrations

23 November 2026. This list distinguishes a confidential app secret from a public OAuth client ID and from a personal token. Redirects in the last column are placeholders for the confidential broker. For vendor OAuth, request the scopes the service documents for its MCP endpoint. For API integrations, the table gives a read-first starting point.

| Service | Kuvo-owned secret and why | Where to register or connect | Scopes to request | Broker redirect |
| --- | --- | --- | --- | --- |
| Slack | **Yes for the confidential MCP broker.** Slack MCP documents a pre-registered app and secret. General Slack OAuth also supports a public PKCE app, so confirm secretless MCP support with Slack before choosing that route. | [Slack API Apps](https://api.slack.com/apps), [Slack MCP setup](https://docs.slack.dev/ai/slack-mcp-server/), [PKCE](https://docs.slack.dev/authentication/using-pkce/) | User scopes `search:read.public`, `search:read.private`, `search:read.im`, `search:read.mpim` for search. Add the matching history scopes for threads and `chat:write` only for sending. | `https://<user-server>/oauth/slack/callback` |
| Discord | **Yes for standard web authorization-code OAuth.** Discord’s documented code exchange uses the registered secret. Server messages require a bot installation and channel permissions. | [Developer Portal](https://discord.com/developers/applications), [OAuth2](https://docs.discord.com/developers/topics/oauth2) | `identify`, `guilds` for user identity and guild listing. For a server bot use `bot`, View Channels and Read Message History, and configure Message Content access where required. | `https://<user-server>/oauth/discord/callback` |
| Google Drive | **Yes for the hosted web app.** Register a Web application. Desktop loopback PKCE is a separate public option. | [Google Auth Platform](https://console.cloud.google.com/auth/clients), [Web OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app) | `https://www.googleapis.com/auth/drive.file` for user-selected files, or `https://www.googleapis.com/auth/drive.readonly` for whole-Drive reads with restricted-scope review. | `https://<user-server>/oauth/google-drive/callback` |
| Gmail | **Yes for the hosted web app.** Register a Web application. Desktop loopback PKCE is a separate public option. | [Google Auth Platform](https://console.cloud.google.com/auth/clients), [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes) | `https://www.googleapis.com/auth/gmail.readonly` for triage. `gmail.compose` for saving drafts and sending, with restricted-scope review. | `https://<user-server>/oauth/gmail/callback` |
| Google Calendar | **Yes for the hosted web app.** Register a Web application. Desktop loopback PKCE is a separate public option. | [Google Auth Platform](https://console.cloud.google.com/auth/clients), [Calendar scopes](https://developers.google.com/workspace/calendar/api/auth) | `https://www.googleapis.com/auth/calendar.events.readonly` for events. Add `calendar.calendarlist.readonly` if listing subscribed calendars. | `https://<user-server>/oauth/google-calendar/callback` |
| Microsoft 365 | **No.** Entra public-client device code uses a registered ID without a client secret. A confidential web app is another option. | [Entra app registrations](https://entra.microsoft.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade), [MSAL flows](https://learn.microsoft.com/en-us/entra/identity-platform/msal-authentication-flows), [Graph scopes](https://learn.microsoft.com/en-us/graph/permissions-reference) | Delegated `Mail.Read`, `Calendars.Read`, or `Files.Read` as needed. Use `offline_access` for renewal. | Device code has no redirect |
| Notion | **No.** The remote MCP endpoint supports dynamic registration and PKCE. | [Notion MCP](https://developers.notion.com/docs/mcp) | `default`; Notion handles consent. | Box loopback |
| Linear | **No.** The remote MCP endpoint supports dynamic registration and PKCE. | [Linear MCP](https://linear.app/docs/mcp) | `read` for triage and `write` when the user needs mutations. | Box loopback |
| GitHub | **No.** The official remote server accepts a personal access token. | [Fine-grained tokens](https://github.com/settings/personal-access-tokens/new), [Official server](https://github.com/github/github-mcp-server) | Selected repositories with **Contents**, **Issues**, and **Pull requests** read access as needed. | None |
| GitLab | **No.** The official server supports dynamic registration or a fine-grained personal token. | [GitLab MCP](https://docs.gitlab.com/user/model_context_protocol/mcp_server/) | Vendor MCP OAuth scope, or MCP tool resource with **Execute** for a fine-grained token. | Box loopback for OAuth |
| Jira and Confluence | **No.** Remote Rovo MCP uses its Atlassian OAuth consent and dynamic registration. | [Atlassian Rovo MCP](https://support.atlassian.com/atlassian-rovo-mcp-server/), [Remote OAuth metadata](https://mcp.atlassian.com/.well-known/oauth-authorization-server) | Scopes requested by Rovo MCP at consent and the signed-in user’s product permissions. | Box loopback |
| Figma | **No separate REST OAuth secret for MCP.** Figma handles remote MCP consent and requires approval for new clients. A REST API fallback requires a confidential registration. | [MCP client waitlist and setup](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/), [REST OAuth apps](https://developers.figma.com/docs/rest-api/oauth-apps/) | Vendor-managed scope for MCP. REST read baseline is `file_content:read` and `file_metadata:read`. | Vendor MCP flow; REST fallback `https://<user-server>/oauth/figma/callback` |
| Asana | **Yes.** Asana MCP V2 explicitly requires a pre-registered client ID and secret and has no dynamic registration. | [Asana Developer Console](https://app.asana.com/0/developer-console), [MCP setup](https://developers.asana.com/docs/integrating-with-asanas-mcp-server) | `default` or omit scope for the MCP app. | `https://<user-server>/oauth/asana/callback` |
| Dropbox | **No.** Register a scoped Dropbox app and allow public clients for PKCE. | [Dropbox App Console](https://www.dropbox.com/developers/apps), [OAuth guide](https://developers.dropbox.com/oauth-guide) | `files.metadata.read`, `files.content.read`; request offline access for turnover. | Box loopback |
| Zoom | **Yes.** Zoom’s documented user-managed General App flow uses the registered client secret. | [Zoom App Marketplace](https://marketplace.zoom.us/), [OAuth apps](https://developers.zoom.us/docs/integrations/create/) | Read-only user meeting scopes for the endpoints used, e.g. `meeting:read:list_meetings` and `meeting:read:meeting`. | `https://<user-server>/oauth/zoom/callback` |
| HubSpot | **Yes.** A HubSpot MCP Auth App supplies both a client ID and a client secret; the flow also uses PKCE. | [HubSpot MCP Auth Apps](https://developers.hubspot.com/docs/apps/developer-platform/build-apps/integrate-with-the-remote-hubspot-mcp-server) under Development | HubSpot determines available scopes from MCP tools. The user selects permissions at install. Start with CRM reads. | `https://<user-server>/oauth/hubspot/callback` |
| Salesforce | **No for a public PKCE client.** The org admin registers an External Client App. A secret can be required by org policy or chosen for a web broker. | [External Client App Manager instructions](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/create-external-client-app.html) | `mcp_api`, `refresh_token` and the org’s required permission sets. | Box loopback, or `https://<user-server>/oauth/salesforce/callback` for confidential policy |
| X | **No for a Native App.** The console issues a public client ID with PKCE. A Web or Automated App is confidential. | [X Developer Console](https://developer.x.com/en/portal/dashboard), [OAuth 2.0](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code) | `tweet.read`, `users.read`, `offline.access`. | Registered public-client redirect |
| Sentry | **No.** Official remote OAuth or an API token using Sentry’s own authorization scheme. | [Official remote server](https://github.com/getsentry/toolkit), [Sentry MCP authorization](https://github.com/getsentry/toolkit/blob/main/docs/cloudflare/oauth-architecture.md) | Sentry MCP consent maps capabilities to API scopes. | Box loopback |
| Stripe | **No.** The remote endpoint supports OAuth dynamic registration and PKCE. | [Stripe MCP](https://docs.stripe.com/mcp) | `mcp` and the selected Stripe account’s access. | Box loopback |
| Supabase | **No.** Official hosted MCP supports dynamic registration. | [Supabase MCP](https://supabase.com/docs/guides/ai-tools/mcp) | Vendor-managed consent; select the intended organization/project. | Box loopback |
| Neon | **No.** Official hosted MCP supports dynamic registration and PKCE. | [Neon MCP](https://neon.com/docs/ai/neon-mcp-server) | `read`, or `write` for mutations. | Box loopback |
| Cloudflare Docs | **No.** Public documentation-search MCP requires no sign-in. Account-management servers are a separate integration. | [Cloudflare MCP servers](https://developers.cloudflare.com/agents/model-context-protocol/mcp-servers-for-cloudflare/) | None | None |
| Hugging Face | **No.** The public catalog tools are open. The service supports a user token for signed-in tools. | [Hugging Face MCP](https://huggingface.co/docs/hub/hf-mcp-server), [User tokens](https://huggingface.co/settings/tokens) | Public tools need none. Use a narrowly scoped user token for private content when supported. | None |
