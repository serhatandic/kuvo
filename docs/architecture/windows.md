# Kuvo on Windows

Work Queue #699 · Design, 22 November 2026 · Source references at `5f36f7184`. The Windows and WSL trial ran on 23 November 2026 (results below).

**Before 0.8, ship the GPUI desktop and both box options: WSL2 and native Windows.** Each works with the app closed, owns its work and pairs directly. Build WSL first to exercise the contracts, then native. The [current architecture](how-kuvo-works.md) removes the need to port split serve and a separate box-services worker. The [engine and browser start on demand](small-computer.md), [accounts use upstream sign-ins](agent-accounts.md), and [one event line per client per box](message-delivery.md) covers reconnects across all transports.

## Desktop and cost

Zed provides GPUI's Win32 windowing, DirectWrite and GPU backend at the dependency in `gpui/Cargo.toml:14` (Windows backend in `gpui/Cargo.lock:2197`). Compile Kuvo at that pin first. Replace Mac bundle and home discovery, use Credential Manager for the desktop pairing key, and give the installed app a signed per-user package and updater (recommend signed MSIX/App Installer, subject to trial). The app invokes the packaged box installer/start command and attaches via `run/serve.json` and loopback HTTP. For WSL it invokes the distro launcher via `wsl.exe` and obtains the record from that distro. Validate the server's build and generation before attaching (`gpui/kuvo_box/src/place.rs:171` currently cannot identify Windows processes). Both use the existing transport, line and browser view. See `gpui/kuvo/src/main.rs:157,177,205`, `gpui/kuvo/src/keeper.rs:27,59`, `gpui/kuvo_box/src/install.rs:42,311` and `gpui/kuvo_box/src/local.rs:83`. [GPUI platforms](https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md), [Zed Windows requirements](https://zed.dev/docs/installation#windows), [App Installer updates](https://learn.microsoft.com/en-us/windows/msix/app-installer/app-installer-file-overview)

WSL reuses the Linux workers, installer and update. Its cost is distro lifecycle, networking and cross-filesystem projects. Native avoids the distro and uses the Windows toolchain directly. Its cost is process ownership, filesystem semantics, installer/startup and worker adapters. Since November 15, both paths have fewer resident processes to launch, one stream to recover, and one release selection to restore. Native still needs the keeper's recovery behavior and agent-holder continuity.

**Trial results, 23 November 2026** (Windows 11 x64, WSL2 Ubuntu 24.04, smoke probes in disposable folders, an administrator account): 15 pass, 8 fail, 1 skipped (ARM64), 2 wait for the user (signing in to the five agents, in WSL and native).

- **WSL works with the existing Linux box**: the engine, resident serve, NAT loopback, cron and systemd, a per-user sign-in task, staying alive through sleep and a closed terminal, and a headless Chrome.
- **Fails to address:** 18, a junction can't be replaced and a running executable can't be deleted (use a plain selector file and clean up busy files later); 19, a headless `conhost` starter hides the exit code, Task Scheduler's retry never ran, and the computer went offline before sign-in (use a starter that passes the status through; the network path before sign-in is part of the startup contract); 20, a streaming stdin/stdout pipe stalled and a listener outlived its SSH session (frame the protocol, own processes apart from SSH); 21, Git Bash makes no real symlinks; 23, Git fails in very long paths and the WSL UNC path failed over SSH; 26, `fsync` on a read-only or directory handle fails with `EPERM`, so the native resident stops at start (`shared/files.ts`'s `syncPath` needs a Windows durability rule).
- **Test runs:** on WSL2 the box passed (93, 2 skipped) and the bridge had 3 failures (bot edit and delete answer 403 where the scenarios expect 404). Native never reached its tests: the runner couldn't use Credential Manager from an SSH sign-in.
- **Fixed by step 3 (8 and 11):** the distro has no SSH server, so Kuvo goes through Windows OpenSSH and `wsl.exe` (binary-clean through cmd.exe and PowerShell), or the paired relay. Projects on Windows drives (DrvFs) get no file events and ignore mode changes, so Changes polls them and Git runs with working-tree mode checks off there; distro-native projects keep file events. The metadata-enabled mount is unverified.
- **Step 3's run on the real PC:** a test Mac added the PC over SSH, enrolled a test home and reached it over a test relay and the OpenSSH hop. A hidden, limited per-user sign-in task kept Kuvo running after the Mac disconnected, and the keeper waited for the add's reservation before starting. Signed fleet switching passed, through the Linux `bin` link. Removal needs the installing account to control its task, so a limited token can delete a task registered over elevated SSH; **Unlink and wipe** then removed the installation and task. Not covered: a fresh standard account, an interop-disabled distro, waking a sleeping PC, and signed-in agent turns.
- Repeat the profile permissions, pipes, links and task registration with a standard account before treating them as release evidence.

## Decisions and access

- **D1–D3.** Use a local NTFS profile with `%USERPROFILE%\.kuvo-code` and checked ACLs. Propose `%LOCALAPPDATA%` if roaming support is needed. Share a box-code keeper with a stable bootstrap that can roll back a broken release. Require user-installed Git for Windows for Kuvo commands.
- **D4, user's decision.** Approve the certificate, name and icon for a small signed, windowless starter. Recommend the starter only launch the box under the user's account. Trial headless launch to confirm what it needs to do.
- **D8–D9.** Default to per-user sign-in startup. Leave pre-sign-in operation and WSL SSH exposure to explicit user setup. Prefer paired relay for WSL. Start with Windows 11 x64 and confirm ARM64 scope and the desktop package channel.

**Needed from the user:** a Windows 11 x64 PC or VM, its tailnet hostname, OpenSSH Server enabled, and a disposable standard-account username with the test SSH public key authorized. Enable WSL2 with Ubuntu 24.04 and provide Git for Windows. Confirm when sleep, sign-out and reboot trials are OK. Keep Defender on and arrange interactive upstream sign-ins as needed. Use an administrator only for user-run setup that requires it. Confirm ARM64 scope and signing details when packaging is due.
