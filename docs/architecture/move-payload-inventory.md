Package 1 of the audit of `4b715e867` covers the contents promised by a move and the evidence required by a move-only wipe. - The link inventories both declared attachment roots for the root session and all its carried children. It also follows managed references in exported records and waiting prompts. Older flat files and files inherited from a different session can enter through these references. Each carried file has its own placement identity, size and SHA-256. A missing managed reference prevents the move. Delivered attachment records with file URLs outside both managed roots are export-only. The removal preview exposes unverified names and export-only records, including unclaimed managed files and computer-local Work Queues.
- The bundle holds file bytes separately from chat records. Installation assigns files an absolute path under the destination session's Box attachment folder. The import rewrites known paths and file URLs in engine exports, native bridge transcript and session metadata, and the waiting queue. Inline-only queued attachments remain in the bundle and queue records. The live wipe challenge covers managed disk payloads. Native agents' private conversation files retain their original format and contents. The moved-session instructions include the old and new paths for references in that private history. Moved payloads are kept with the destination session and are excluded from the ordinary 14-day upload cleanup.
- Work Queue attachment names come from item records. New uploads keep their SHA-256 in the item record. Older records retain their declared size and acquire a digest when staged for a move. Destination placement verifies bytes before publishing, journals the item records it can roll back, and marks installed directories so an interrupted import can clear just its own files. Backup sealing independently checks persisted digests while reading the bytes fed to encryption.
- Artifact history and retained versions are export-only for this move protocol. The artifact journal selects promised content-addressed copies, and export checks size and hash. Ordinary working files outside managed roots still follow the existing bot-folder or explicitly selected project rules. An expired file cannot be recovered by export unless a prior independent copy has it.
- A payload-bearing move and every prepared-removal move require a peer that acknowledges verification for that bundle. The destination checks installed bytes again at activation and when replaying the decision after a lost reply. A legacy ordinary move with a recognizable attachment note and no matching inventory is refused. Historical references outside recognizable attachment records and pre-upgrade sources already authorized to erase remain compatibility boundaries.
- Before reporting wipe readiness, the source challenges the destination to verify the accepted set of move decisions and their bytes. After source writers stop, the detached wipe worker makes a fresh check over the scoped removal channel. A missing or changed file withholds erase. A move or export plan can be revised through the existing explicit operation revision flow when no prior wipe authorization is outstanding. A pre-upgrade authorization may require reconciliation with the source before it can be revised.
