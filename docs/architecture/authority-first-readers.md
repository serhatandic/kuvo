## Downgrade rule

An incompatible disk format must use a separate path that older binaries never read, rewrite or clean up. The upgrade must test the preceding reader at its original path, the new reader at both paths as applicable, and interrupted upgrade and downgrade with the new bytes intact. Downgrades remain available. Use additive v1 at an existing path only when the preceding reader gives those bytes the same meaning.

This change adds only compatible fields to existing paths. The actual audit predecessor fixture still runs original settings and repair readers and reopens the resulting legacy bytes with the new link. The new fixtures cover direct HTTP requests and replies, the media header, helper and update supervision, and rehome refusal before native work. The app-owned last-wipe gap belongs to the separate wipe task.
