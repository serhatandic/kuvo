# #920 · Storage and message version inventory

Baseline is piece T at `819e4f5a6`. Scope is the computer's Kuvo home (including the old Mac home when imported), external computer backup storage, and the Box's public protocol. The ownership draft is organized by user data. The rows below group files that share one versioning contract. Counts are of families, including generated or third-party families. An "unmarked" row has no independent version for its contents at baseline. A build string, ID, timestamp, revision, cursor or encryption algorithm is separate from a schema version.

The folder version at `folder-version.json` advances through the ordered steps in
`box/src/shared/folder-version.ts`. A missing marker means layout 0. Each step starts with
a journal checkpoint in that same file and commits its new version atomically. A restart
replays an unfinished step and skips committed steps. The 0.5–0.7 import runs in step 1
when rehome supplies a staged copy. Rehome publishes the checkpoint with its staged data
and rolls the staged move back if interrupted before placement is committed.

Existing family markers still validate their content, including signed bytes, per-record
JSON, and SQLite schemas. A layout checkpoint does not authorize rewriting a family with
an unsupported content version. Existing family readers and writers retain their checks.

Layout 1 is additive so pre-marker builds can still use the folder during rollback. A
future incompatible layout must run with old writers stopped and include a compatible
rollback plan. Wire compatibility remains governed by each message's existing contract.
