mail authentication, and durable letter retry and receipt state. The server consumes session events
and owns HTTP requests and sockets. Setup and peer features consume authenticated mail and supply
the trusted roster, conversation lookup, and idempotent engine submission.

Of the 86 scenarios catalogued here, 9 are covered, 26 are partial, and 51 remain at consuming
feature boundaries. Session setup with a one-time token, installer claims and grant negotiation are
setup work (2.2–2.3). Calls and seats remain on disk for their respective consumers. Ordered relay
echoes for work-start delivery fences belong with the work-start policy.

The live test runs the production relay and TypeScript box in a scratch home. A prepaired Rust
desktop opens a session and reads `kuvo/info`. A Rust computer in the TypeScript roster reopens
its outbox, sends a sealed letter, authenticates the TypeScript receipt, and retires the send. The
TypeScript home starts with the letter's prior acceptance on disk to simulate a lost receipt.
This exercises the production mail handler without starting an engine. After building the
TypeScript bundles and installing the relay dependencies, run it with
`KUVO_RS15_BUN=/path/to/bun scripts/cargo-box.sh test -p kuvo_peers --test relay -- --ignored`.

The shared `wire.json` vectors are generated by the TypeScript box's actual mail, Noise, document,
and sorted JSON code. The tests also read `link.json`, `noise.json`, and the existing `docs.json`
fixture directly. Generate the phase 1.5 additions before running the Rust wire tests on a fresh checkout.

```sh
UPDATE_WIRE_VECTORS=1 scripts/test-box.sh box test/wire-vectors.test.ts
scripts/cargo-box.sh test --locked -p kuvo_wire -p kuvo_peers
```

The generator writes the ignored `protocol/vectors/wire.json`. Cargo embeds that file in the test
executable so the same vectors can run on hosts without Bun.
