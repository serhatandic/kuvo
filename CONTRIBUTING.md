# Contributing to Kuvo

Thanks for helping improve Kuvo. It's meant to stay small, fast and native, so
the best changes keep the app light: no web views, few dependencies, and no
work done while nobody is looking.

## Before opening a change

- Search existing issues and pull requests first.
- Open an issue before starting a large feature, a new dependency, or a change
  to how the VM is set up. Small fixes don't need prior approval.
- Keep pull requests focused. Separate mechanical moves from behavior changes.
- If the change is user-facing, say what the docs at
  [kuvo.run/docs](https://kuvo.run/docs/) need to cover.

## Development setup

You need a Mac with Apple silicon, macOS 15 or later, and Xcode 16 or later
(Swift 6).

```sh
git clone https://github.com/serhatandic/kuvo.git
cd kuvo
./scripts/run.sh
```

`run.sh` makes a debug build, signs it with the virtualization entitlement the
VM needs, and runs it. To build the release app the way CI does:

```sh
./scripts/build-app.sh
open build/Kuvo.app
```

The same binary is the `kuvo` command. Run it with arguments to use the CLI
from a debug build, for example `.build/debug/Kuvo ls`.

### The icon

The app icon is generated by `scripts/icon.py` as an Icon Composer file in
`Resources/AppIcon.icon`, and compiled into `Resources/Icon` by
`scripts/build-icon.sh`, which needs Xcode 26 or later. The compiled files are
committed, so you only need this when changing the icon.

### Dependencies

Kuvo depends on swift-argument-parser and SwiftTerm. If you add or update a
package, run `./scripts/third-party-licenses.sh` and commit the updated
`THIRD_PARTY_LICENSES.txt`; CI checks that it's current.

## Pull requests

Describe what changed, why it changed, and how you verified it. Keep commit
messages short and factual. Don't include generated build output, credentials,
personal paths, AI session metadata, or co-author trailers added by coding
tools.
